# 多会话通知目标设计

状态：用户已确认并完成实现，待提交。

## 目的与现状

用户希望从当前 QQ Bot 已建立的群聊和私聊会话中选择多个通知目标。私聊在现有单选列表和两种发送链路中已经受支持：目标须先收到一条私聊消息、进入上游 peer 映射及会话列表，才可选用。本次重点是多选、目标状态隔离和控件体验，不新增任意 openid 输入或突破 QQ 平台限制。

当前 `settings.defaultTargetSessionId` 与 `feature.target.sessionId` 都是单个字符串。CS2 已通知记录 `seen` 与偶尔闲聊的 `lastSentAt`、`lastTopicId` 也属于整个模组。直接循环发送会造成第一个目标占用去重或冷却，使后续目标收不到消息。

## 方案

| 方案 | 取舍 |
| --- | --- |
| 在功能运行时逐目标调用现有 provider，并隔离每个目标的状态（采用） | 所有模组沿用同一投递语义；内置模组分别记录去重与冷却；扩展模组仍接收单个 `target.sessionId`，无需更改接口。 |
| 各模组自行实现多目标循环 | CS2、闲聊及扩展模组会出现不同的失败和去重语义，重复逻辑多。 |
| 只在全局发送器中复制消息 | 发送器不了解每个模组的 `seen` 与冷却，无法正确处理部分成功和重试。 |

## 配置与迁移

- 新配置使用 `settings.defaultTargetSessionIds: string[]` 和 `feature.target.sessionIds: string[]`。数组去重、保序，只接收非空且不超过 120 字符的会话 ID；每组最多 20 个目标，避免意外的大范围推送。旧 `defaultTargetSessionId`、`target.sessionId` 自动读取为单元素数组；新保存只写数组。
- 模组目标数组为空表示**继承整组全局默认目标**；非空表示**整组覆盖**，不与全局目标合并。启用模组时有效目标至少一个；已启用继承模组存在时不可清空全局默认目标。
- 保留旧单目标的已通知和闲聊状态：将旧 `seen`、`lastSentAt`、`lastTopicId` 归属到升级前的有效会话 ID。新加入的目标没有历史发送记录。状态以会话 ID 为键；不在有效目标组中的记录保留 30 天后清理，避免无限增长。

## 运行与结果

- `run()` 按有效目标顺序逐个调用现有 provider，每次仍传单个 `{ sessionId }`。CS2 赛事数据和规则共用，已通知记录按目标独立；偶尔闲聊的概率、冷却、上次话题按目标独立。立即操作作用于当前有效目标组，CS2「立即发送」对每个目标重发。
- 每个目标的成功提交及分段成功后立即保存对应的已通知状态。一个目标失败时继续处理其他目标；失败的赛事或分段不标记成功，同一目标之前成功的分段仍保留记录。运行结果以 `targetResults: [{ sessionId, matched, sent, error, warning, skipped, channel }]` 报告逐目标状态，同时保留现有顶层 `matched`、`sent` 汇总与 `error`；`sent` 只计已确认调用或提交的赛事。界面明确显示部分成功；用户再次「立即检查」时仅补发尚未成功的 CS2 通知。服务回合提交和上游发送调用仍不等于 QQ 客户端送达。
- CS2 三条规则之间的现有优先级和 30 秒间隔保留。一次规则检查内部按目标顺序处理，不同时发起多个 QQ 请求。失效或已确认不可用的群目标报错，不阻止其余目标；私聊按现有会话映射发送。
- 扩展模组也由运行时逐目标调用，但其自定义持久状态仍由模组自行管理；运行时只隔离内置模组的 `seen`、冷却和上次话题字段。此边界在开发说明中写明。

## 控件与反馈

- 全局默认、CS2、偶尔闲聊和通用扩展卡片使用同一多选控件：可搜索的勾选列表、已选数量与可移除的目标标签；每项显示名称、群聊／私聊类型和会话 ID 末尾。窄侧栏中标签与按钮换行，不依赖原生多选框的键盘组合操作。
- 保留「刷新选项」，打开列表时也刷新会话；刷新后即时更新候选项，同时保留未保存的选择。失效目标或不可用群在已选区明确标识，可移除但不可重新勾选。模组显示「继承全局默认（N 个目标）」入口；用户选择任一独立目标后，使用独立目标组。
- 保存前提示空目标、失效目标和继承范围；运行反馈按目标展示成功／失败，而不是把部分成功显示为全成功。控件具备可读标签、键盘焦点、浅深主题及约 390px 容器的可操作布局。
