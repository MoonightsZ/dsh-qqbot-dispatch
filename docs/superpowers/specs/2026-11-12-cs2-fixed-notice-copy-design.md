# CS2 固定通知文案设计

状态：用户已确认设计，功能已实现并通过测试，待提交。

## 意图

让每日赛程汇总、赛前提醒和赛果提醒在 QQ 中各有清晰的用途与识别方式，减少三种通知都像同一份赛事清单的感觉。此次只调整由赛事数据确定性生成的固定 Markdown；不调用 AI，不改变通知时机、去重、投递方式或现有的可选 AI 焦点分析功能。

## 方案选择

| 方案 | 取舍 |
| --- | --- |
| 调整现有三种固定内容排版（采用） | 改动集中，可保持现有数据、分段、预览与发送链路；每种通知固定使用一种风格。 |
| 为固定内容增加用户可编辑模板 | 灵活，但要增加占位符校验、迁移和界面；当前需求未要求个性化编辑。 |
| 为每种通知做多套随机轮换 | 有变化，但同一种通知的辨识度下降，预览及问题复现也更复杂。 |

## 三种格式

| 规则 | 固定格式 | 数据边界 |
| --- | --- | --- |
| 每日汇总 | 日期与总场数开头；按赛事分组，每组列出比赛时间、双方队伍与可用的 Bo 信息。多赛事时保留分组标题，长内容沿用现有分段。 | 只使用已筛选的目标日期赛事；赛事名、时间、Bo 来自数据源。 |
| 赛前提醒 | 每个赛事一张简短对阵卡：醒目的「即将开赛」与赛事名，下方列出对局、开赛时间和可用的 Bo 信息；同赛事多场合并。 | 不编造倒计时或焦点分析；开赛后仍不补发。 |
| 赛果提醒 | 标明「已确认赛果」；比分不相等时突出比分较高的一方获胜，同时展示完整对阵比分。同赛事多场合并，比分相等时仅展示比分。 | 仅按数据源明确完赛且有效的比分生成胜者结论；不描述地图、回合、逆转或胜因。 |

三种通知都保留 Liquipedia 链接与 CC BY-SA 3.0 标注。缺少 Bo 或赛事等级时自然省略，不显示空标签。发送与设置页的「实际效果预览」共用同一组格式化函数，使预览对应真实发送内容。
