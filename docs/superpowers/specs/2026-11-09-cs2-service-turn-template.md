# CS2 服务回合生成模式

CS2 赛事通知新增投递模式：`direct`（现有直发优先并在失败时回退服务回合，默认）和 `service-turn`（只提交服务回合，由 Agent 生成回复）。旧配置继续使用 `direct`。模式与 Markdown 模板只属于 CS2 模组，保持现有调度、筛选、去重及“立即发送”重发语义。

`service-turn` 模式每个赛事提交一个服务回合。插件先按赛事整理匹配对局，再将结构化赛事事实与用户可编辑的 Markdown 模板交给 Agent。默认模板按“赛事标题 → 对局 → 焦点分析 → 数据来源”排列，提供 `{{tournament}}`、`{{tier}}`、`{{matchups}}`、`{{focusAnalysis}}`、`{{sourceUrl}}` 占位符。除 `{{focusAnalysis}}` 外，其余占位符由插件填入。模板必须包含 `{{matchups}}`、`{{focusAnalysis}}`、`{{sourceUrl}}` 及 Liquipedia 来源标注，长度不超过 6000 字符。页面提供恢复默认模板按钮。

焦点分析仅使用本次获取的赛事数据和当前会话上下文，可讨论比赛时间、对阵与已知赛制；不得编造战绩、阵容、胜率、地图或比赛结果，也不让 Agent 自行联网。焦点对局优先选 24 小时内的关注队伍比赛，否则选赛事中最早的一场。服务回合模式不直发图文卡片；切回直发模式后原卡片设置仍保留。

服务回合成功提交后沿用现有去重记录，但页面明确显示“已提交服务回合，QQ 送达待确认”。没有匹配赛事时不提交回合。群不可用检查由现有服务回合入口执行。模式转换不清除历史去重记录。
