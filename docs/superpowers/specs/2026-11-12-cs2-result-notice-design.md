# CS2 赛果提醒设计

状态：用户已确认设计与后续调整，待最终验证。

## 意图与范围

在 CS2 模组中加入与每日赛程汇总、赛前提醒并行的「赛果提醒」。复用现有 Liquipedia MediaWiki `Liquipedia:Matches` API、目标会话、队伍与等级筛选、全局投递方式。新增规则默认关闭，每 15 分钟检查；只处理开赛时间在最近 6 小时内、数据源标记已完赛且双方比分有效的比赛。按比赛独立去重；手动「立即发送」可重发符合条件的赛果。

## 已核实的数据边界

当前公开 API 的同一比赛块包含 `data-finished="finished"` 与两个比分元素。现有解析器尚未提取这些字段。该接口没有可用的完赛时间，因此 6 小时窗口只能根据开赛时间计算；超长比赛可能在窗口外才完赛。进行中比分、未完赛、无比分、`0:0` 和无效比分均不发送。

## 方案

| 方案 | 取舍 |
| --- | --- |
| 复用现有 MediaWiki API（已选） | 沿用现有请求节流与缓存；需补充分数和状态解析，并依赖页面结构。 |
| 单独使用 LiquipediaDB API | 结构化赛果更完整，但需要额外访问权限与凭证，现有插件不能直接使用。 |

## 行为与页面

- `result` 规则拥有独立开关、间隔或 Cron、运行结果、下次执行和手动操作；升级旧配置时保持关闭。
- 固定内容包含赛事、双方队伍、最终比分、来源与版权标注。AI 焦点分析模式使用赛果专用模板，只能依据已提供的比分与会话上下文措辞，不补造地图、回合、原因或战绩。
- 赛果已通知记录使用独立键，不影响赛前提醒和每日汇总。一次检查多场结果时沿用现有按赛事分组及分段策略，发送失败的场次不标记成功。
- 全局直接发送 Markdown 时隐藏模板编辑，预览赛果固定内容并用红字说明原因。
- 文档说明数据来源、6 小时窗口、去重和服务回合提交不等于 QQ 送达。

## 验证

覆盖完赛与进行中比分解析、无效比分、6 小时边界、三条规则独立执行与状态、重发和失败去重、模板与界面展示；运行全套测试和前端构建。

## 后续调整：优先级队列与旧通知移除

- 自动检查同时到期时按赛前提醒、赛果提醒、每日汇总依次处理。实际发送或提交后，下一条规则至少间隔 30 秒，并在间隔到期后的下一次调度检查中继续处理；无匹配内容的检查继续处理下一条。
- 待检查规则持久化，重启后继续处理；超过 1 小时的待检查项失效。赛果提醒按原到期时间判断 6 小时窗口，避免错峰导致边界赛事漏发。手动操作不进入队列。
- 移除旧版通知规则、发送范围、编辑入口和模板选择。旧配置只含该规则时不自动启用其他规则；原自定义模板仍用于迁移到现有规则的模板字段。
- 队列只能控制插件提交间隔。服务回合的实际 QQ 到达顺序取决于上游，同一规则的多段消息仍可能连续到达。
