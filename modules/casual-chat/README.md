# 偶尔闲聊

在指定 QQ 群聊定时检查触发条件，偶尔发起简短聊天。模组默认关闭；可同时选择最多 20 个群聊。目标群聊不选择时继承[全局默认目标](../../README.md#全局默认目标会话)中的群聊，单独选择则整体覆盖全局设置。私聊不参与本模组；旧配置中的私聊目标运行时会跳过。

## 自动触发

| 设置或限制 | 默认值 |
| --- | --- |
| 每日检查时间 | 19:00，时区 `Asia/Shanghai` |
| 触发概率 | 30% |
| 安静时段 | 22:00–09:00 |
| 距上次发送的冷却时间 | 至少 72 小时，可设为 1–720 小时 |

检查时间、概率、冷却小时数、安静时段和群聊偏好均可在功能页修改。每个群聊独立计算冷却；一个群聊处理失败不阻止其他群聊。已有按天保存的冷却配置会自动换算为小时；旧的 `|` 或换行分隔话题会自动迁移为列表。

## 群聊话题来源

使用服务回合投递时，Agent 首先参考当前群聊会话中可见的最近讨论，选一个适合公开接续的话题。如果没有合适内容，且 Agent 配有 `web_search`，则检索与本群兴趣相关的近期公开话题。搜索不可用或结果不可靠时，参考备用话题或提出一般性问题。可选填“群聊兴趣方向”和“避谈内容”；无需维护话题池。群成员原话、姓名、OpenID、私聊和附件内容不得作为搜索词。

这里依赖 Agent 可见的会话上下文和已配置的搜索工具；被其他模组过滤、未进入该会话的消息不会成为话题依据。搜索工具不可用时不会阻止服务回合提交。服务回合已提交不代表 QQ 已送达。

## 备用话题池与 AI 推荐

每条话题可以启停、编辑、删除，并配置多个标签。输入主题词后点击“AI 推荐”，可编辑和勾选候选；点击“加入话题池”后，还需点击页面“保存”才会生效。推荐使用 DSH 已配置的首个可用模型；没有可用模型时仍可手动维护话题。生成时的主题词会单独保留，默认也用作新话题的标签（主题词超过标签长度上限时只保留来源）。AI 推荐不会读取 QQ 会话内容，也不会自动向 QQ 发送消息。

抽取时先等概率选择一个有启用话题的标签，再在标签内随机选话题；多标签话题按标签数降低单次权重。无标签话题归入“未分类”。若池为空，使用三个内置话题。服务回合仅把抽中的话题作为备用提示；直接发送时尽量避开上一条已调用上游发送方法的话题，若池中话题全部禁用则跳过直接发送。

「立即发起」会先保存当前设置，再跳过自动触发限制。

## 投递方式

全局选择服务回合投递时，Agent 按上述顺序生成开场白；选择直接发送 Markdown 时，只能将备用话题原文交给上游 QQ Bot 发送方法，不会读取群聊上下文或使用搜索工具。上游发送方法已调用不代表 QQ 已送达。全局开关及限制见[根目录说明](../../README.md#全局投递配置)。
