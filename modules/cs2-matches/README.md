# CS2 赛事通知

按设定的间隔或 Cron 检查 Liquipedia 赛程，筛选关注队伍与赛事等级，并向指定 QQ 会话发送通知。

## 配置与操作

可设置数据源、关注队伍、赛事等级、目标会话、检查间隔或 Cron 规则。队伍与等级留空时不按对应条件筛选。

| 操作 | 效果 |
| --- | --- |
| 立即检查 | 仅处理尚未通知过的匹配赛事。 |
| 立即发送 | 先保存当前配置，再发送所有匹配赛事，包括已通知过的赛事。 |

页面显示匹配数量与发送或提交数量。发送失败的赛事不会被记录为已通知；服务回合提交成功仍不代表 QQ 已送达。

## Cron 规则

每条规则使用独立输入框，以数组保存。页面会解释规则，并显示按设定时区计算的下一次执行时间；修改后需保存才会更新。

支持五段格式「分 时 日 月 周」、`*`、`*/步长`、数字列表和范围。日期与星期同时指定时须同时满足。旧版以 `;` 分隔的规则仍可读取，保存后转为数组。

## 内容生成方式

「固定赛事内容」（默认）提交已排版的赛事正文；「AI 焦点分析」让 Agent 根据赛事数据和已有会话上下文，在可编辑的 Markdown 模板中填写焦点分析。分析不自行联网，也不应编造战绩、阵容或胜率。

默认模板：

```md
# {{tournament}}

{{tier}}

## 对局
{{matchups}}

## 焦点分析
{{focusAnalysis}}

---
数据来源：[Liquipedia]({{sourceUrl}}) · CC BY-SA 3.0
```

模板必须保留 `{{matchups}}`、`{{focusAnalysis}}`、`{{sourceUrl}}` 和 Liquipedia 来源标注。全局切换到直接发送 Markdown 时，内容生成方式和模板暂不可编辑，只发送固定赛事正文；已保存的选择会保留，切回服务回合投递后生效。投递方式见[根目录说明](../../README.md#全局投递配置)。
